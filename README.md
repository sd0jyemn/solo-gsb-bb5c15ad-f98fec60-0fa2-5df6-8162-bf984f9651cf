# 字幕断句(Subtitle Segmenter)

基于 FastAPI + 原生 HTML/JavaScript 的字幕断句网页应用。用户粘贴带时间戳的词序列,可标记不可拆短语、按词间隙设置边界约束(必须断开/禁止断开);系统在「每条最多两行、行宽与阅读速度限制」下,用全局动态规划选择分段,使 **镜头切点偏差 + 行长不均 + 不自然停顿** 的加权总代价最低。页面实时展示断句预览与逐段代价,调整约束或权重即时重算;无可行方案时定位首个冲突区间(或首个不可行的必须断开边界)及原因,页面保留输入与标记并高亮冲突。

## 启动

```bash
docker compose up --build
```

依赖安装与应用初始化均随容器启动自动完成,无需本地环境。

## 访问

- 网页界面: http://localhost:8000
- API: `POST http://localhost:8000/api/segment`

## 边界约束

在「边界约束」面板中点击词间隙,循环切换三种状态:

| 状态 | 标记 | 含义 |
| --- | --- | --- |
| 必须断开 | ✂ | 该词间隙必须成为分段边界(硬约束) |
| 禁止断开 | 🔗 | 该词间隙不得成为分段边界(硬约束) |
| 清除 | · | 无约束(再次点击即可清除) |

- 约束随每次请求提交,在全局动态规划中作为硬条件生效;蓝色下划线表示当前方案的实际断点。
- 不可拆短语内部的词间隙不得设置边界(页面中锁定,API 侧返回 422)。
- 若必须断开导致任一侧违反时长、行宽或阅读速度限制,响应返回 **首个不可行边界** 及具体原因(`conflict.boundary` 为词间隙下标,`conflict.side` 为 `left`/`right`,`conflict.reasons` 为违例列表),页面高亮该间隙。

### API 数据模型

请求体新增可选字段 `boundaries`(缺省时行为与此前完全一致):

```json
{
  "words": [{"text": "我们", "start": 0.5, "end": 0.9}],
  "phrases": [[4, 5, 6]],
  "shots": [4.5],
  "config": {"w_shot": 1.0},
  "boundaries": {"must_break": [7], "no_break": [1, 2]}
}
```

- `must_break` / `no_break`:词间隙下标列表,下标 `i` 表示词 `i-1` 与词 `i` 之间的间隙(`1 <= i <= 词数-1`)。
- 校验失败返回 422:下标越界、同一边界既必须断开又禁止断开、边界落在不可拆短语内部。
- 冲突响应在原有 `conflict`(`word_range`/`start`/`end`/`text`/`reasons`)基础上,边界冲突时额外携带 `boundary` 与 `side` 字段;成功响应结构不变。

## 配置

无需环境变量;所有参数在网页左侧面板调整(也可通过 API 的 `config` 字段传入):

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `max_chars_per_line` | 42 | 单行最大字符数(硬约束,每段最多 2 行) |
| `max_cps` | 20 | 最大阅读速度,字/秒(硬约束) |
| `min_duration` | 0.8 | 每段最短时长,秒(硬约束) |
| `max_duration` | 7.0 | 每段最长时长,秒(硬约束) |
| `pause_threshold` | 0.3 | 词间间隔小于该值视为不自然断点,秒 |
| `shot_dev_cap` | 0.5 | 镜头切点偏差归一化上限,秒 |
| `crossing_penalty` | 1.0 | 分段跨越一个镜头切点的惩罚 |
| `w_shot` | 1.0 | 权重:镜头切点偏差 |
| `w_imbalance` | 1.0 | 权重:行长不均 |
| `w_pause` | 1.0 | 权重:不自然停顿 |

## 输入格式

- **词序列**:每行 `开始 结束 文本`,时间支持 `HH:MM:SS.mmm` 或秒数;也接受 JSON 数组 `[{"text","start","end"}]`。
- **不可拆短语**:每行一个,词下标区间(如 `3-6`,含端点)或短语原文(自动匹配首个连续出现)。
- **边界约束**:在词序列间隙上点击设置(见上节),随请求自动提交。
- **镜头切点**:每行一个时间点。
